# I did it.

> 계획은 가볍게 세우고, 해낸 일은 선명하게 남기는 개인용 주간 투두리스트

## 프로젝트 소개

`I did it.`은 일주일의 계획을 한눈에 확인하고, 완료한 일과 놓친 일을 명확하게 구분할 수 있도록 만든 개인용 웹 애플리케이션입니다. 단순히 할 일을 관리하는 데서 끝나지 않고, 완료한 행동이 캐릭터의 성장과 꾸미기 보상으로 이어지도록 설계해 작은 성취를 계속 쌓는 경험을 제공합니다.

## 기획 배경

기존 투두리스트는 해야 할 일을 입력하고 체크하는 기능에는 충실하지만, 시간이 지나면 미완료 항목이 쌓이거나 완료 기록의 의미가 흐려지기 쉽습니다. 이 프로젝트는 다음 질문에서 시작했습니다.

- 한 주의 계획과 결과를 동시에 볼 수 없을까?
- 지나간 기록은 보존하면서, 놓친 일만 자연스럽게 다시 계획할 수 없을까?
- 완료 행동 자체가 계속 사용하고 싶은 동기가 될 수 없을까?

## 핵심 목표

1. 월요일부터 일요일까지의 계획과 진행 상태를 한 화면에서 확인한다.
2. 과거 기록은 수정할 수 없게 보존해 실제 행동 기록의 신뢰성을 유지한다.
3. 미완료 일정은 다른 날짜로 이월해 계획을 유연하게 조정한다.
4. 완료한 일의 누적을 캐릭터 성장과 장식 보상으로 시각화한다.
5. 주간 기록뿐 아니라 월간 진행률도 쉽게 돌아볼 수 있게 한다.

## 주요 기능과 설계 의도

### 주간 보드

- 한 주를 7개의 날짜 열로 표현했습니다.
- 접속 시 오늘 날짜가 화면 중앙에 오도록 해 현재 해야 할 일에 바로 집중할 수 있습니다.
- 과거 날짜는 잠기며, 당시의 완료·미완료 상태가 그대로 보존됩니다.

### 일정 이월

- 과거의 미완료 일정만 이월 날짜를 표시합니다.
- 오늘이나 미래 일정의 복사는 단순 일정 조정으로 보고 원래 날짜를 노출하지 않습니다.
- 루틴은 반복 규칙 자체가 일정의 기준이므로 다른 날짜로 복사하거나 이동할 수 없습니다.

### 루틴 관리

- 반복 요일과 기간을 설정해 매일 해야 하는 일을 관리할 수 있습니다.
- 각 날짜의 루틴 목록은 기본적으로 접어 화면의 복잡도를 줄였습니다.
- 미래 날짜에서는 완료할 수 없고, 완료된 루틴은 일반 일정과 구분되는 초록색으로 표시됩니다.

### 성장형 캐릭터

- 완료한 전체 일의 개수에 따라 먼지가 5단계로 성장합니다.
- 성장 기준은 3개, 5개, 10개, 20개, 30개입니다.
- 완전히 성장한 뒤에는 추가 10개 완료마다 장식 선택권을 얻습니다.
- 리본과 새를 미리 비교한 뒤 적용할 수 있으며, 같은 위치의 장식은 동시에 착용할 수 없습니다.

### 완료 도장과 월간 기록

- 하루의 모든 일정을 완료한 경우 날짜 옆에 `내가 해냄` 도장이 표시됩니다.
- 월간 기록에서는 오늘까지의 완료율, 완벽한 날, 일반 일정, 루틴, 연속 달성을 확인할 수 있습니다.
- 미래 일정은 현재 진행률 계산에서 제외해 수치가 불필요하게 낮아지지 않도록 했습니다.

### 데이터 저장

- 별도의 회원가입 없이 브라우저 `localStorage`에 데이터를 저장합니다.
- 새로고침 후에도 기록이 유지되지만, 다른 브라우저나 기기와 자동 동기화되지는 않습니다.
- 포트폴리오 공개 버전에는 개인 일정이나 테스트 데이터가 포함되지 않습니다.

## 프로젝트 구조

```text
.
├── src/
│   ├── assets/          # 성장 단계와 장식 이미지
│   ├── components/      # 헤더, 주간 보드, 날짜 열, 카드와 모달
│   ├── hooks/           # 플래너 상태·동작, 저장, 오늘 날짜 갱신
│   ├── utils/           # 날짜, 루틴 규칙, 월간 집계와 테스트
│   ├── constants/       # 저장 키와 장식 설정
│   ├── App.jsx          # 화면 구성과 상태 연결
│   ├── main.jsx         # React 앱 진입점
│   └── styles.css       # 전체 UI 스타일
├── index.html
├── package.json
└── README.md
```

## 코드 구성과 검증

화면은 컴포넌트, 상태와 동작은 `usePlanner`, 저장과 날짜 갱신은 전용 훅으로 분리했습니다. 월간 집계는 화면 없이 테스트할 수 있는 순수 함수로 관리합니다. 저장 키를 유지해 구조 변경 후에도 기존 기록을 불러옵니다.

검증은 `npm test`와 `npm run build`로 실행합니다. 날짜 경계, 루틴 기간, 미래 일정 제외, 윤년의 빈 통계를 테스트합니다.

## 주요 UX 판단

| 문제 | 적용한 방식 | 의도 |
| --- | --- | --- |
| 과거 기록이 쉽게 바뀜 | 과거 날짜 수정 잠금 | 행동 기록의 신뢰성 유지 |
| 미완료 일정이 방치됨 | 날짜를 선택해 복사 | 실패가 아닌 재계획으로 전환 |
| 반복 일정이 화면을 차지함 | 루틴 기본 접기 | 일반 일정에 대한 집중 유지 |
| 완료 경험이 일회성임 | 성장·장식 보상 | 장기적인 사용 동기 제공 |
| 미래 일정 때문에 진행률이 낮아짐 | 오늘까지의 일정만 집계 | 현재 성취를 왜곡하지 않음 |

## 데이터 저장 방식

현재는 별도의 가입 과정 없이 사용할 수 있도록 데이터를 브라우저에 저장합니다.

## 향후 개선 방향

- **데이터 백업**: 기록을 파일로 내보내고 다시 가져오는 기능을 추가해 브라우저 변경이나 데이터 삭제에 대비하고자 합니다.
- **기기 간 동기화**: 선택적으로 로그인 기능을 제공하고, 클라우드 저장소를 연결해 여러 기기에서 기록을 이어갈 수 있도록 개선하고자 합니다.
- **키보드 접근성**: 키보드만으로 일정 추가·완료·날짜 선택과 모달 조작이 가능하도록 개선하고자 합니다.
